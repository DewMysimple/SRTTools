# 系统架构

## 模块职责与边界

- React 页面和统一工具工作区负责输入、参数、分页预览、错误和导出反馈。Zustand 管理文件队列和会话状态。TypeScript 核心以整数毫秒、稳定 cue ID 和独立诊断表示字幕。[模块与模型](../../docs/ARCHITECTURE.md)
- Agent 在 0.1.0 采用了纯 TypeScript 引擎、独立 Worker 和 Rust 文件服务，落实原需求的 UI 与引擎分离、批量处理保持可响应和最小系统访问。现有批次顺序运行并逐文件隔离失败，可取消和重试。顺序调度限制处理并发，批量吞吐取决于串行任务耗时。[调度实现](../../src/services/processing-service.ts)
- Rust 管理原生路径权限和发布输出。桌面默认目录是可记忆的偏好，每次启动重新授权。导出以临时文件完整写入后发布，重名追加序号。[原生 IPC](../../src-tauri/src/commands/mod.rs) · [写入实现](../../src-tauri/src/commands/safe_files.rs)

- 0.4.0 Agent依据第四阶段任务书采用单一无UI操作registry、严格schema和线性内存流程；编辑/预览复用原参数表单/diff，纯Chinese跨度写回，混合有损须显式同意。[流程架构](../../docs/ARCHITECTURE.md)
- 0.5.0 Agent 采用独立 SRT 编辑草稿和稀疏历史，以共享 Worker、校验、序列化、差异预览和安全另存为实现闭环。哈希数据路由拦截切换，主窗口监听原生关闭；列表和轨道仅挂载视口附近及点击槽内的条目。[时间轴架构](../../docs/ARCHITECTURE.md#字幕时间轴)
- 0.6.0 Agent 采用 WebView2 的实际媒体时间与本地订阅驱动光标、进度和字幕叠加，复用区间索引。播放、seek 和 A/B 状态与字幕编辑历史分开。[媒体架构](../../docs/ARCHITECTURE.md#本地视频同步预览)
- 0.6.1 Agent 在 AppLocalData 保存带版本和摘要的已提交字幕快照。前端按 revision 串行，Rust 保留最后有效版本并按源字节指纹核对恢复冲突。[草稿原生服务](../../src-tauri/src/commands/drafts.rs)
- 0.7.0 Agent 对校准采用整数比值和单次毫秒舍入。预览与 revision、锚点及范围绑定，超过 10,000 条复用 Worker 传时间元数据，应用经同一字幕事务、历史和草稿路径。[校准核心](../../src/features/timeline/core/precision-calibration.ts)
- 流程键workflow-presets-v1独立于旧工具键；共享串行队列/Web Locks与原生两键CAS、browser exact-raw journal提供事务和恢复。目录输出由native root metadata与同一树计划驱动，授权token/句柄锁/guard和原子无覆盖写入限制范围。[预设交换](../../src/services/preset-exchange.ts)、[目录导出](../../src-tauri/src/commands/folder_export.rs)

## 数据流与依赖

- 文件服务读取字节 → 调度器创建 Worker → Worker 解码、解析、校验、处理、序列化和编码 → 工作区显示诊断和预览 → 用户确认后导出。桌面通过受限 IPC 导出，浏览器通过 Blob 下载，多结果 ZIP 使用按需加载的 JSZip。[文件服务](../../src/services/file-service.ts) · [Worker](../../src/workers/worker-logic.ts) · [导出服务](../../src/services/export-service.ts)
- 原生拖放先登记授权再发事件。Tauri Store 通过固定键访问设置、历史和预设，历史保存摘要元数据。浏览器预览使用 localStorage。[原生入口](../../src-tauri/src/lib.rs) · [持久化](../../src/services/persistence.ts) · [历史](../../src/services/history-service.ts)
- v0.2.0 由序列化器提供匹配实际输出字段的快照，差异层利用可信 cue ID、内容锚点和有界局部匹配。多输入合成显示输出概览。展示层不参与编码和写盘。[架构](../../docs/ARCHITECTURE.md#处理前后差异)
- 预设通过独立固定键 `tool-presets-v1` 保存声明参数。前端按工具和 schema 校验，应用时清除旧结果。Windows Store 常规写入采用同目录原子替换，遇错误码 17 用恢复文件保护已提交值。[预设服务](../../src/services/preset-service.ts) · [原生命令](../../src-tauri/src/commands/mod.rs)
- 简繁使用解析器可选正文跨度，在 Worker 内写回源布局后重解析验证；编码器分段及整份严格往返，诊断含条目/元数据和 scalar。独立对比在同一 diff 核心关闭 ID 信任、仅分类时使用容差，JSON 只写数量摘要。批量页沿原 ToolWorkspace/预设存储。[核心和 Worker](../../docs/ARCHITECTURE.md)
- 文件夹扫描通过 Channel 逐份交付和唯一终态，前端等命令与终态都完成才解锁。Windows 同句柄读取、最终路径核对和祖先目录锁限制范围。Explorer 使用首注册的 single-instance 与具体路径 pending，空闲后消费；仅 HKCU owner/path 专属键和安全 NSIS hooks。[原生边界](../../docs/ARCHITECTURE.md#ipc-与文件边界)
- 原生视频选择器只颁发一份本地只读文件的令牌，后端固定 `srtmedia` 源、1 MiB Range、4 个请求和 WebView2 缓存绕过。页面切换、关闭或重载撤销会话。Gate 4 原生回执验证大文件 seek 与旧令牌 404。[媒体访问实验](../../docs/MEDIA_ACCESS_SPIKE.md)

## 运行与部署

- Windows 开发按 [README](../../README.md) 使用 Node.js 24 LTS、Rust stable MSVC、C++ Build Tools、Windows SDK 和 WebView2。浏览器用 `npm run dev`，原生开发用 `npm run tauri -- dev`。
- `npm run release:win` 在干净源码上执行质量门槛、真实 NSIS 打包、ZIP 解压与 UIA 冒烟，再将最新一套可回滚替换到 `release-output/`。运行仍需系统 WebView2，缺失时安装器配置下载引导，当前未签名。`dist/target` 只作中间产物，默认保留编译缓存。未知文件/外部 target/运行进程/唯一旧副本受保护。[发布策略](../../docs/RELEASE_POLICY.md)

- 第五阶段Agent沿用现有发布事务，提取[版本检查](../../scripts/check-versions.mjs)供CI/发布/verify复用，覆盖npm双lock版本、Tauri、Cargo app及锁条目；About仍导入npm版本。Windows CI和发布加入[真实PS5解析/BOM门槛](../../scripts/check-windows-scripts.ps1)。原生QA等待目标页面和可用UIA模式、仅在本次自有窗口可见点拖放，用户Store/注册表按既有持久备份与Job机制恢复。
- 上游NOTICE由显式资源白名单随ZIP/NSIS分发，Git仅对该许可数据保留原始字节和上游空白；源码/脚本正常diff检查。业务引擎与权限边界本轮未变。
- 0.5.0 在旧工作流基础上，将便携版的时间轴原生验收与固定 Setup 的安装/时间轴/卸载恢复纳入晋升门槛。验证器按候选版本检查，旧版产物仍可安全回滚。[发布策略](../../docs/RELEASE_POLICY.md)
- 0.6.0 另外要求 ZIP 解压版和 Setup 安装版各有七项真实媒体证据。测试主机用 FFmpeg 生成合成样本，发行资源白名单保持应用与第三方许可两项。[发布策略](../../docs/RELEASE_POLICY.md)
