# 已知问题

## 未解决问题与影响

- Windows 11、100% DPI 和已装 WebView2 的环境已有安装版证据。Windows 10、无 WebView2 的干净系统、125% / 150% / 200% DPI 未验。传统 MAX_PATH 以上的系统选择器与所有入口的预算组合未全面覆盖；0.4流程/目录与固定Setup已通过本机真实验收，文件夹/CLI具体限额分项实测，见测试记录。
- 当前 NSIS 安装包未配置签名。格式与功能限制另见[功能文档](../../docs/FEATURES.md)。
- 本机 Win11 的 HKCU 菜单登记和 Shell 查询成功，真实传统菜单未显示应用项，因此菜单显示/点击导入 BLOCKED。Agent 按第四阶段任务书可选Explorer项 采用实验性、默认关闭和登记状态不声称可见的降级；CLI 转发、物理拖放、启停/更新/路径修复/卸载保护及恢复有独立原生 PASS。未把 UAC 推测写成已证实根因。[本轮审阅](../../docs/REVIEW_v0.2.0_to_v0.3.0.md)

- 自动审批拒绝了 Firefox15文件/279,726B、根test-results16文件/300,276B的精确清理；旧target/smoke隔离QA201文件/11,106,633B此前也被拒。保持原状，未改工具绕过；它们不进入发行包。大qa-v011与旧安装器已安全清除，正式发布目录无历史套件累积。[清理边界](../../docs/TESTING.md#失败诊断与清理边界)

- 独立Worker OS峰值仍NOT_MEASURED；Node阶段采样与页面heap不能代表完整Worker/应用峰值。当前重复生命周期1017创建/终止、active0/max1，未以有限采样宣称全环境无泄漏。[性能范围](../../docs/PERFORMANCE_v0.4.0.md)

## 复现与临时处理

- 原生拖放可报告独占锁导致的读取失败并隔离其他文件。系统选择器打开同一锁定文件的 UI 自动化未完成，复现路径见[原生验收矩阵](../../docs/RELEASE_CHECKLIST_v0.1.1.md)。
- 在相应 Windows 版本、DPI 和无 WebView2 的环境按矩阵补测。原生权限、超长路径和批量预算分别查看自动化与桌面覆盖范围。
- 需要正常可验证用户环境补验 Explorer 菜单显示。本轮未为通过该项而改机器级设置或默认文件关联；可继续使用文件选择、目录导入和拖放。
