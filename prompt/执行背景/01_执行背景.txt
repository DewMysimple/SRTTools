
## 二、用户体验优化：让工具真正好用

P1

建议作为 v0.2.0 的核心方向

你的软件已经有统一工具页面、只读预览、结果导出和历史记录，因此不需要重新设计整个 UI。

我更建议增强现有组件。

### 1. 更直观的处理前后对比

目前已经支持预览和分页，下一步可以考虑做成左右对比，并高亮真正发生变化的位置。

实现时建议在现有 `src/components/tool-workspace.tsx` 的基础上扩展 `PreviewPanel`，不要重新创建独立编辑器。

### 2. 智能推荐工具

目前已经有工具分类和搜索。我建议进一步增加根据文件情况推荐操作的能力。

例如：

用户导入一个 SRT，软件检测到编号异常、空白字幕、文本过长时，在文件概览中展示：

> 检测到 3 个问题，推荐使用「重新编号」「删除空白字幕」和「自动换行」。

这个功能不需要 AI，直接复用 `src/core/validate.ts` 中的规则就可以实现。用户也不必先知道应该打开哪个工具。

### 3. 最近使用参数与工具收藏

例如用户经常使用「查找替换」，每次都需要重新输入类似的参数。

可以支持保存预设：

- 清理字幕空格。
- 规范化中文字幕。
- 移除指定格式标记。
- 常用替换规则。

这会为后面的批量处理流程提供基础。

## 三、下一轮最有价值的功能扩展

我对照了仓库的 [FEATURES.md](https://github.com/DewMysimple/SRTTools/blob/main/docs/FEATURES.md?utm_source=chatgpt.com)。这些是当前明确没有覆盖，或者值得增强的能力。

GitHub



| 功能               | 建议优先级 | 原因                           |
| ---------------- | ----- | ---------------------------- |
| 简繁字幕转换           | 高     | 高频中文使用场景，独立工具容易理解            |
| GBK / GB18030 导出 | 高     | 当前可以手动导入，但不能导出这些编码           |
| 保存工具预设           | 高     | 减少重复设置，方便批量使用                |
| 可视化差异对比          | 高     | 当前字幕对比主要生成 JSON 报告，普通用户不容易阅读 |
| Windows 右键菜单集成   | 中     | 直接在 Explorer 中发送文件到工具箱       |
| 文件夹批量导入          | 中     | 支持整个文件夹导入、筛选字幕文件             |
| 组合处理流程           | 中     | 一次执行清理、替换、修复和导出              |
| 智能语义断句           | 低     | 当前主要是字符规则换行，语义断句需要更多工作       |

其中，我最看好两个方向。

第一是保存工具预设。 比如用户可以保存一套“中文字幕规范化”规则，下次打开其他字幕文件时直接使用。它既适合普通用户，也能为批量工作流打基础。

第二是可视化字幕对比。 仓库目前已经实现了字幕差异报告，但主要以 JSON 形式输出。可以增加一个普通用户能看懂的对比界面，按字幕编号展示新增、删除、修改和时间差异。这样不必引入完整字幕编辑器，也能带来明显的使用价值。

| 优化方向   | 实施建议                                             |
| ------ | ------------------------------------------------ |
| CI 自动化 | 每次 push / PR 自动运行 lint、TypeScript、Vitest、Rust 检查 |
| 发布流程   | 通过 Git tag 触发 Windows 构建，生成 GitHub Release 草稿    |
| 版本管理   | 统一 npm、Tauri、Cargo 中的版本                          |
| 回归测试   | 建立真实字幕文件语料库，涵盖各种编码和异常格式                          |
| 自动更新   | 稳定公开发布后接入 Tauri Updater                          |
| 签名     | 正式分发前评估 Windows 代码签名                             |

特别要区分两件事：Windows 安装包的代码签名，以及 Tauri Updater 用于验证更新来源的签名，不是同一套机制。Tauri 官方要求更新包必须进行签名验证。

[image](https://www.google.com/s2/favicons?domain=https://v2.tauri.app\&sz=32)

Tauri



另外建议增加一类测试：无损性与幂等性测试。

例如删除空格时，不能意外修改字幕时间；重新编号时，不能改变字幕正文；对已经规范的字幕再执行一次规范化，结果应该保持一致。尤其是当前统一模型导出会重新序列化文件，这类测试值得持续完善。

原生交互验收、安装兼容性、回归测试、CI 工作流、修复发现的问题。

## v0.3.0 — 实用功能扩展

第三阶段

目标：补齐常用字幕处理能力。

简繁转换、GBK/GB18030 导出、Windows 右键菜单、文件夹批量导入、可视化字幕对比。

## v0.4.0 — 高级效率工具

后续规划

目标：让高频用户能够更高效地处理大量字幕。

组合处理流程、预设导入导出、批量文件夹处理、性能基准测试和大文件能力优化。

## 六、我最建议你坚持的一条产品原则

SRTTools 的竞争力不应该来自工具数量，而应该来自“安全、快速、可预测地完成字幕处理”。

建议让几位没有开发背景的用户实际体验：给他们一份乱码字幕、一份需要替换文本的字幕和一组需要批量处理的文件。观察他们能否不看说明独立完成，以及在哪一步容易困惑。

这类反馈往往比增加十个新功能更有价值。

如果现在由我来安排下一轮 Codex 开发任务，我会先做 v0.1.1 稳定性验收 + v0.2.0 的预览对比和参数预设。现有架构基本可以保留，逐步改进即可。
