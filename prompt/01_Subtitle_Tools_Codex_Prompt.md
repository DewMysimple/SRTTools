# 1. 产品定位与原则

## 1.1 产品定位

Subtitle Tools 是一款面向普通用户的 Windows 桌面字幕工具箱，主要处理 SRT
文件，同时逐步支持 VTT、ASS、SSA、TXT、CSV 等字幕及文本格式。

用户无需了解字幕文件内部格式，也无需学习复杂操作，只需：

**选择文件 → 选择工具 → 设置参数 → 预览结果 → 执行处理 → 导出文件。**

## 1.2 核心原则

-   极简：清爽、克制、清晰，不堆砌信息。
-   易用：功能名称使用普通用户能理解的中文。
-   本地优先：基础字幕处理在本机完成，不依赖服务器。
-   安全：默认不覆盖原文件，执行前尽可能提供预览。
-   稳定：正确处理编码、换行、多行字幕、时间边界和异常文件。
-   可扩展：每个工具独立，底层处理逻辑可复用。
-   可测试：核心处理逻辑与 UI 分离，重要算法有自动化测试。

## 1.3 明确不做的事情

本产品不是专业视频字幕制作软件。第一阶段不开发： -
视频播放器或视频预览。 - 可视化时间轴或多轨道字幕编辑。 - 视频剪辑。 -
复杂的专业字幕制作工作流。

时间相关功能只提供简单的参数化批处理，例如整体提前或延后若干毫秒。第一阶段不将
AI 翻译、AI 润色或云端服务作为必需功能。

## 2.2 技术边界

**React / TypeScript 负责：** - 所有页面和 UI 组件。 -
字幕文件解析、序列化和大部分业务处理。 -
文本清理、时间计算、字幕合并拆分。 - 检测规则和修复策略。 -
任务状态、处理预览和结果展示。 - 可复用工具配置表单。

**Tauri / Rust 负责：** - 系统文件选择对话框。 - 本地文件读取与写入。 -
文件夹选择和必要的文件系统操作。 - 系统级集成。 - 在 TypeScript
或浏览器环境不适合时，承担经过验证的编码转换等原生操作。

不要为了使用 Rust 而把所有字幕业务重写成
Rust。优先让核心业务保持为独立、可测试的 TypeScript 模块。

**安全约束：** - 使用 Tauri 2 的安全模型和最小权限 capabilities。 -
配置合理的 CSP 和安全 IPC 边界。 - 只授予应用实际需要的文件权限。 -
不开放任意命令执行。 - 不把用户输入直接拼接进 Shell 命令。 - 不暴露
Node.js API；Tauri 前端不依赖 Node Integration。 -
所有文件读写都通过明确封装的文件服务完成。 -
不将用户字幕文件自动上传到网络。

2.  **全部工具**：按分类展示所有字幕工具。
3.  **批量处理**：多个文件执行相同或组合操作。

5.  **设置**：主题、语言、默认输出目录、文件命名规则等。

不要为每个小工具创建复杂的独立导航层级。工具详情页通过统一页面模板承载。

## 3.1 首页

首页包括产品名称和简短说明、文件拖放区域、"选择文件"按钮、常用工具快捷入口、最近处理文件、批量处理入口和简单使用提示。

支持拖入一个或多个文件。根据文件类型给出合理反馈；不支持的文件要显示原因。

## 3.2 全部工具

以分类卡片或简洁列表展示工具。每个工具显示图标、工具名称、一句话说明。提供工具搜索，支持按名称和关键词过滤。

## 3.3 批量处理

提供文件队列，展示文件名、文件类型、文件大小、处理状态、成功或失败信息和输出文件名。支持添加文件、移除文件、清空列表、开始处理、取消尚未开始的任务、打开输出目录。

## 3.4 处理记录

记录任务时间、工具名称、输入文件数量、成功数量、失败数量、输出目录和任务摘要。历史记录不应保存字幕全文，只保存必要的任务元数据。

## 3.5 设置

至少提供： - 浅色 / 深色 / 跟随系统主题。 - 默认导出目录。 -
默认导出文件名规则。 - 默认编码和换行符。 -
处理完成后是否自动打开输出目录。 - 是否显示处理前预览。 -
清理处理历史。 - 软件版本信息。

默认主题为浅色。

# 4. 工具功能范围

工具分为七个类别。第一版优先完成标记为 P0 的功能。

## 4.1 文本处理

  功能           优先级   说明
  -------------- -------- ------------------------------------
  查找和替换     P0       普通文本查找替换，支持区分大小写
  删除空白字幕   P0       删除纯空格、空行或无可见内容的字幕
  删除重复字幕   P1       可选择完全相同文本或连续重复项
  空格清理       P0       清除行首行尾空格、连续空格
  标点转换       P1       中英文标点互转
  简繁转换       P1       使用可靠的简繁转换库，注明转换局限
  英文大小写     P1       大写、小写、首字母大写
  字数限制       P1       检测或限制每行字符数
  自动断句       P1       根据用户设置的每行字符数换行
  文本提取       P0       提取字幕纯文本，可选择保留换行
  HTML 清理      P1       删除 HTML 标签，谨慎处理实体
  关键词过滤     P2       根据关键词保留或删除字幕条目

文本处理默认只改字幕正文，不改变时间信息和条目顺序。每项工具必须清晰说明处理范围。

查找替换默认使用普通文本模式。正则表达式可作为高级选项，必须校验表达式并捕获错误，不能让非法表达式导致应用崩溃。

## 4.2 字幕合并与拆分

  功能           优先级   说明
  -------------- -------- ------------------------------
  多文件合并     P0       合并多个 SRT 文件
  双语字幕合并   P1       将两份字幕按时间或编号匹配
  按时间拆分     P1       按指定时间点或时间范围拆分
  按条数拆分     P1       每个输出文件包含指定条数
  字幕匹配       P2       按开始时间容差进行匹配
  字幕对比       P1       比较两个文件的文本和时间差异

合并功能必须提供明确策略： - 按文件顺序合并。 - 按时间排序合并。 -
保留原始时间或按用户指定策略处理。

双语合并时，用户可以选择按编号匹配，或按开始时间匹配并设置时间容差；还可以选择中文在上
/ 英文在下，或反向。

不能假定两份字幕一定一一对应。未匹配条目必须在结果摘要中显示，不能静默丢弃。

## 4.3 格式转换

  输入   输出
  ------ -------------------------------------------------------
  SRT    VTT
  VTT    SRT
  SRT    TXT
  SRT    CSV
  CSV    SRT
  SRT    ASS
  ASS    SRT
  SSA    SRT
  TXT    SRT（仅在文本包含可识别时间信息或用户提供映射规则时）

要求： - 转换前检查格式。 - 转换后生成结果摘要。 -
对有损转换给出提示。 - ASS / SSA 转 SRT
时，说明字体、颜色、位置、样式、特效等可能丢失。 - TXT 转 SRT
不得凭空编造时间戳；缺少时间信息时，应提示用户使用模板或提供映射规则。 -
CSV 必须使用明确的列结构和正确的引号转义规则。 - VTT 的 `WEBVTT`
头、时间分隔符和 cue 设置需要正确处理。

## 4.4 检测与修复

检测项目： - SRT 结构异常。 - 编号缺失、重复或不连续。 -
时间格式错误。 - 结束时间早于或等于开始时间。 - 时间倒序。 -
字幕时间重叠。 - 空字幕。 - 重复字幕。 - 字符异常或疑似乱码。 -
字幕正文过长。 - 单条字幕显示时间过短或过长。

修复原则： -
明确无歧义的问题可以一键修复，例如重新编号、删除纯空白条目。 -
有多种修复方式的问题必须先让用户选择策略，例如时间重叠、结束时间异常。 -
修复前提供预览或修复摘要。 - 显示问题所在的字幕编号和原因。 -
不得悄悄改变字幕正文或时间。 - 修复完成后重新运行检测，显示剩余问题。

## 4.5 时间处理

不提供时间轴，只提供表单参数： - 整体提前或延后指定毫秒 / 秒数。 -
批量增加或减少显示时长。 - 按指定时间范围裁剪。 - 时间格式规范化。 -
设置最短显示时长。 - 设置最长显示时长。

时间内部统一使用整数毫秒，不使用浮点数累计时间误差。

任何操作都必须检查时间不得小于
0、结束时间必须大于开始时间、时间偏移后是否出现无效条目、裁剪后是否出现空区间。如果操作会产生无效时间，不要自动静默修正；应显示异常并让用户选择修复策略。

## 4.6 文件处理

-   识别常见文本编码。
-   UTF-8 与 UTF-8 BOM 转换。
-   UTF-16 LE / BE 转换。
-   在经过测试的前提下支持 GBK / GB18030 等常见中文编码。
-   CRLF / LF 换行符转换。
-   批量重命名。
-   文件信息查看。
-   字幕条目数量统计。
-   字符数量统计。
-   字幕时间跨度统计。
-   生成空白 SRT 模板。

编码识别可能不准确，必须提供手动选择编码的能力。检测结果不确定时，应提示用户确认，不要把乱码内容当作正常文本覆盖原文件。

## 4.7 批量处理

第一版支持对多个文件执行同一操作： - 批量文本替换。 - 批量时间偏移。 -
批量格式转换。 - 批量编码转换。 - 批量检测。 -
批量修复明确无歧义的问题。 - 批量重命名。 - 批量导出 ZIP。

后续再增加可保存的自定义处理流程。第一版不需要复杂的节点式流程编辑器。

# 5. 统一工具页面交互规范

所有工具尽量复用统一页面模板，避免重复开发。

建议组件： - `ToolPage`：工具页面外框、标题、说明和操作区。 -
`FileSelector`：文件选择和拖放。 - `FileList`：已选文件列表。 -
`ParameterForm`：工具参数表单。 - `PreviewPanel`：处理前后预览。 -
`ResultPanel`：成功、失败、警告和统计信息。 -
`ExportPanel`：导出文件和打开目录。 - `ConfirmDialog`：危险操作确认。 -
`EmptyState`：空状态。 - `ErrorState`：错误状态。

## 5.1 标准操作流程

1.  选择文件。
2.  设置参数。
3.  点击"预览"或"开始处理"。
4.  查看影响摘要和异常提示。
5.  确认执行。
6.  选择输出位置或使用默认位置。
7.  导出文件。

简单且无风险的工具可以减少步骤，但不能牺牲数据安全。

## 5.2 交互要求

-   所有按钮都必须有真实功能。
-   处理中显示进度或明确的忙碌状态。
-   处理期间防止重复提交。
-   错误信息使用普通用户能理解的语言。
-   错误详情可以展开查看。
-   空状态应告诉用户下一步怎么做。
-   操作成功后显示结果摘要和导出入口。
-   处理失败时保留输入文件和用户参数，方便重试。
-   不要使用浏览器 `alert()`、`confirm()` 作为主要交互。
-   对批量任务显示整体进度和单文件状态。
-   对可能耗时的任务提供取消能力；如果某个任务无法安全取消，应明确说明。

字体：统一标题、正文、辅助说明、代码/时间文本样式。 -
状态：hover、focus、active、disabled、loading。

使用 CSS 变量或 Tailwind theme
管理主题，避免在各个组件里散落硬编码颜色。

## 6.4 易用性和无障碍

-   所有输入框有明确 label。
-   图标按钮提供 tooltip 或 aria-label。
-   键盘焦点清晰可见。
-   对比度足够。
-   不单独依赖颜色表达成功、失败和警告。
-   表单校验错误显示在对应字段附近。
-   时间和文件名使用易读、可复制的格式。

# 7. 核心数据模型与字幕引擎

字幕处理引擎是整个项目的核心。所有工具必须复用统一的数据模型，不能各自解析
SRT。

建议模型：

``` ts
export interface SubtitleCue {
  id: string;
  index: number;
  startMs: number;
  endMs: number;
  text: string;
}

export interface SubtitleDocument {
  id: string;
  fileName: string;
  sourcePath?: string;
  format: "srt" | "vtt" | "ass" | "ssa" | "txt" | "csv";
  encoding: string;
  lineEnding: "CRLF" | "LF" | "CR";
  cues: SubtitleCue[];
  modified: boolean;
}

export interface ParseDiagnostic {
  severity: "info" | "warning" | "error";
  code: string;
  message: string;
  line?: number;
  cueIndex?: number;
}
```

字段可以按实际实现调整，但必须保留以下原则： - 时间统一用整数毫秒。 -
每条字幕有稳定的内部 ID。 - 字幕编号与内部 ID 分离。 -
正文支持多行文本。 - 文件格式、编码和换行信息应有明确记录。 -
解析诊断与字幕数据分开。

## 7.1 SRT 解析要求

SRT Parser 必须处理： - 标准时间格式 `HH:MM:SS,mmm`。 -
导入时可容忍使用点号作为毫秒分隔符的非标准文件。 - UTF-8 BOM。 -
CRLF、LF 和 CR 换行。 - 字幕正文中的多行文本。 -
编号缺失、重复、不连续。 - 空字幕。 - 文件末尾没有额外空行。 -
条目之间存在多个空行。 - 文件开头或时间行周围存在多余空白。 -
非法时间行和不完整条目。

不能简单地对整个文件使用 `split("\n\n")`
后假定每段都合法。解析器需要能返回可读诊断，尽可能恢复可恢复条目，同时标记无法解析的内容。

## 7.2 SRT 序列化要求

-   输出标准 SRT 时间格式 `HH:MM:SS,mmm`。
-   编号默认从 1 连续递增。
-   每条字幕之间使用一个空行。
-   正文多行结构必须保留。
-   可选择输出 CRLF 或 LF。
-   编码由导出设置决定。
-   输出前校验时间有效性。
-   序列化结果应可再次被 Parser 正确解析。

## 7.3 时间工具函数

建立独立、经过测试的工具： - `parseTimestamp()` - `formatTimestamp()` -
`millisecondsToTimestamp()` - `timestampToMilliseconds()` -
`shiftCueTimes()` - `validateCueTime()`

不要在不同页面重复实现时间解析逻辑。

# 8. 文件读写、编码与安全策略

## 8.1 文件导入

-   使用 Tauri 原生文件选择对话框。
-   支持多选文件。
-   支持拖放文件。
-   校验扩展名，同时不能只依赖扩展名判断实际格式。
-   文件读取失败时显示具体原因。
-   不支持的格式不得强行解析。
-   允许用户手动选择文件编码。
-   文件过大时显示提示，避免无反馈地卡住 UI。

## 8.2 编码策略

至少测试 UTF-8、UTF-8 BOM、UTF-16 LE、UTF-16 BE。对 GBK / GB18030
等中文编码，只有在所选库确实支持并通过测试后才开放。

编码自动检测不是百分之百可靠： -
显示检测结果和置信程度（如果库能提供）。 - 提供手动覆盖选项。 -
检测不确定时提示用户确认。 -
不允许在不提示的情况下把可能乱码的文本写回文件。 -
转换后应验证可解码，并对无法表示的字符提供警告或替代策略。

## 8.3 导出与原文件保护

-   默认不覆盖原文件。
-   默认文件名建议为 `原文件名_processed.ext`。
-   如果目标文件已存在，自动提供不冲突的名称，或让用户确认。
-   支持"另存为"和选择输出目录。
-   写入失败时保留处理结果，允许重新选择目录。
-   不应在导出过程中破坏已有文件。
-   采用安全写入策略：先写临时文件，成功后再替换目标文件（如适用）。
-   导出前确认扩展名和实际内容格式一致。

## 8.4 文件系统权限

优先使用 Tauri 官方 dialog、fs、store 等插件，并按实际需求配置
capabilities。不要授予不必要的全盘读写权限。若使用 Rust
Commands，必须校验参数和路径，并将命令范围限制在用户明确选择的文件或目录内。

# 9. 批量处理与任务管理

建立统一任务模型，例如：

``` ts
export type TaskStatus =
  | "queued"
  | "processing"
  | "success"
  | "failed"
  | "cancelled";

export interface BatchFileTask {
  id: string;
  inputPath: string;
  inputName: string;
  status: TaskStatus;
  outputPath?: string;
  errorMessage?: string;
  warnings: string[];
}
```

要求： - 一个文件失败不能导致整个批次崩溃。 -
显示总文件数、已完成数、成功数、失败数。 - 对每个文件显示独立状态。 -
可以重试失败项。 - 可以移除尚未开始的任务。 -
取消操作不能导致半写入文件被误认为成功。 -
批量导出支持保留原文件名并追加后缀。 - ZIP
打包前检查重名文件，不能静默覆盖 ZIP 内的同名条目。 -
任务结束后提供结果摘要和输出目录入口。

第一版可以按顺序处理文件，确保稳定；不要为了并发而引入不必要的复杂性。若采用并发，必须限制并发数并测试内存使用。

对于耗时的解析、批量处理或大量文本转换，评估使用 Web Worker，避免阻塞
React 主线程。

# 10. 错误处理与数据可靠性

建立统一错误类型或错误码，至少区分： - 文件读取失败。 -
文件编码无法识别。 - 格式不支持。 - 字幕解析失败。 -
字幕数据校验失败。 - 参数无效。 - 文件写入失败。 - 输出文件冲突。 -
用户取消操作。 - 批量任务中的单文件失败。

错误信息分两层： 1. 面向普通用户的简洁说明。 2.
可展开查看的技术详情，便于排查。

不要吞掉异常，不要只在控制台打印错误。开发环境可以输出调试信息，生产环境避免泄露本地敏感路径或字幕全文。
