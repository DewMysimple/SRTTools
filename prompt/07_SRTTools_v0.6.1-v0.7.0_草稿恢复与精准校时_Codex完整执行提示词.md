# 3. Gate 1 — v0.6.1：草稿持久化架构与原子写入

**目标：** 编辑后发生进程崩溃、Windows 意外重启或应用异常终止时，可以恢复已经成功写入本地的编辑进度；不会因断电留下“看似成功、实际上损坏”的草稿。

## 3.1 复用现有编辑会话

- 查清现有时间轴的 `SubtitleDocument` 原始快照、草稿、dirty 状态、撤销/重做与编辑事务分界。
- 只观察**已提交的修改**（例如拖拽 pointerup、精确时间提交、正文输入确认、插入/删除、撤销/重做）；临时拖动预览、视频播放游标移动、滚动/缩放、A/B 循环播放等不得触发字幕草稿改动。
- 将草稿存储视为编辑事务的异步副作用，不让磁盘 I/O 每次渲染或鼠标移动都发生。
- 使用独立 `DraftRecoveryService`（命名可调整），提供 `scheduleSave`、`flush`、`listRecoverable`、`load`、`validate`、`discard`、`prune` 等明确职责；不在 React 组件中直接散落文件写操作。
- 采用版本化的草稿 Envelope，给未来 schema 升级留出迁移/兼容入口。

### 建议数据结构（示意，不要求逐字段复制）

```ts
interface DraftEnvelopeV1 {
  schemaVersion: 1;
  draftId: string;
  source: {
    displayName: string;
    path?: string;            // 当前用户明确打开的字幕路径；新建文件可无
    sourceSize?: number;
    sourceMtimeMs?: number;
    sourceSha256?: string;    // 对原文件字节计算，用于检测外部变化
  };
  baseDocumentHash: string;  // 用户开始编辑时的文档基线摘要
  savedAt: string;           // ISO 日期时间
  committedRevision: number; // 单调递增的编辑版本号
  format: 'srt';             // v0.6.x 时间轴完整编辑格式，其他格式依现有保真策略处理
  encoding: string;
  lineEnding: 'CRLF' | 'LF' | 'CR';
  cues: SubtitleCue[];      // 只保存字幕和最小必要元数据；不含任何视频字节
}
```

**注意：** 具体 `SubtitleDocument` 字段以仓库当前 `src/core/models.ts` 为准。导入/恢复时不得直接信任 JSON；必须通过运行时 schema 校验、时间与字幕完整性检查。恢复出来的 cue ID 必须稳定，`index` 与稳定 ID 不能混淆。

## 3.2 保存策略

- 默认开启「自动保护未保存字幕草稿」，在设置页面提供明确的开启/关闭说明和本地占用空间提示。
- 推荐在每次已提交编辑事务后使用 **1–2 秒 debounce**，在编辑持续发生时设置合理的最长延迟（例如不超过 15 秒）；关键边界（文件切换、退出确认、显式导出）执行可等待的 `flush`。
- 存储成功后才标记相应 `committedRevision` 为已保护；不能仅因调度了写入任务就显示“草稿已保存”。
- 异步写入按文档 ID + revision 串行化。较旧任务不得覆盖较新草稿；快速切换文件、批量撤销、关闭窗口时必须保证顺序与取消/清理语义正确。
- 对未完成的临时拖拽操作，不产生恢复点；拖拽提交后再调度写入。
- 用已存在的应用本地数据路径（例如 Tauri appLocalDataDir 对应位置）存储；不要把草稿写到源码仓库、安装目录、`release-output/` 或用户视频目录。
- 首次启动和跨版本升级不应破坏既有 settings / history / presets，避免重复存储历史字幕全文。

## 3.3 原子性和崩溃一致性（P0，必须真实实现）

首选借助经审查的 Rust 原生文件服务实现本地事务式草稿写入；如现有 Tauri 存储插件提供相同保证，也可复用，但必须有真实故障注入测试。

**最少保障：**

1. 草稿写入到**同目录临时文件**，完整写入并校验长度/内容摘要后再提交。
2. 使用适合 Windows 语义的原子替换或「不可变版本化快照 + 原子更新索引」策略；**不可先删掉上一份可恢复草稿再写新草稿**。
3. 写入文件、更新 manifest、删除过期临时件的顺序要保证任一阶段崩溃时仍能读取最后一份完整快照。
4. 尽可能执行 flush/sync 与目录元数据刷新；Windows 下如果某个文件系统不能提供强原子性保证，应在 QA 说明限制，并以版本化快照恢复兜底。
5. 每份快照至少含 schema version、byte length、SHA-256 或等价完整性校验。无效临时快照不可成为“最近成功保存”。
6. 写入失败不得破坏上次成功草稿；必须在 UI 标记「草稿保护失败」，允许重试或手动导出。
7. 处理 Windows 文件占用、杀毒临时锁、权限不足、磁盘空间不足、路径过长等常见异常，不能让崩溃传播到 React 渲染主线程。
8. 保存任务应是明确单向的事务，不根据未校验的用户提供路径执行任意删除/覆盖。

### 草稿存储目录的边界

- 单草稿建议大小软/硬上限分别为 **8 MiB / 16 MiB**，总草稿预算默认 **64 MiB**，可恢复草稿数量上限建议 **20 份**；如果 50,000 条字幕的真实样本超过上限，要依据基准调整并记录理由。
- 对达到上限的活跃未保存草稿**不得无提示地清除**。先清理已恢复/已确认丢弃的草稿、孤立临时文件与已确认无效的旧快照；仍超限时停止新增自动写入并明确警告，提供安全管理入口。
- 记录 30 天以上的草稿可以标记「旧草稿」，但不能在用户未确认的情况下自动永久删除唯一的未恢复版本。为减少磁盘增长，提供可预览空间与手动删除能力。
- 同一草稿可保留有限的最近完整快照用于回滚（例如 2 个），删除前须确认至少一份完整可信的最新快照存在；不能无限生成 `.bak.1`、`.bak.2`、`.bak.3`……
- `release-output/`、`src-tauri/target/` 和用户媒体缓存不应成为草稿持久化位置。此处的空间预算与构建缓存清理是两个独立问题。

## 3.4 隐私与安全

- 不上传草稿、源字幕或媒体内容。
- 草稿中不保存当前选中的视频文件字节、视频令牌、媒体 URL、临时授权句柄或历史播放内容。
- 本地草稿可能包含敏感字幕文本，设置页需明确告知位置/保存方式，并提供“清理所有已恢复/已放弃草稿”和“逐项管理可恢复草稿”。
- 不在 console、错误遥测、CI 日志或 Git 仓库中写入用户真实字幕全文、完整私人路径或原始草稿 JSON。
- 文件名和路径来自用户输入，要拒绝目录穿越、设备路径滥用、非法符号链接等风险；只允许写入应用受控的草稿根目录，调用 Rust 时进行路径规范化与边界检查。
- 若未来要增加草稿加密，应另做威胁建模；本次不为了形式上的“加密”引入无效的硬编码密钥。

# 4. Gate 2 — v0.6.1：恢复、冲突检测和完整用户交互

## 4.1 恢复发现时机

启动应用、重新打开某个字幕文件或进入时间轴工作区时，检查匹配的**未完成、未导出、完整可信**草稿。不要每次导航都弹一次相同对话框：在当前会话中记录用户选项，尊重「稍后处理」。

恢复卡片应显示：
- 字幕文件名、最后成功保护时间。
- 原字幕与草稿的差异摘要，例如改变的字幕条目数、时间变化数、正文变化数、插入/删除数。
- 草稿实际空间、来源文件是否一致、草稿安全状态。
- 按钮：**恢复草稿**、**查看差异**、**稍后处理**、**丢弃草稿**。

UI 风格沿用原来的浅色极简工具箱和时间轴工作区。复用已有逻辑对齐/差异预览组件，**不要新写一套字幕 diff 算法**。

## 4.2 恢复语义

- 「恢复草稿」只恢复到**内存编辑会话**，标记 `dirty=true`；不得在用户未确认时直接覆盖源字幕或自动导出。
- 恢复字幕后继续使用现有编辑事务、撤销重做、时间校验和普通另存为流程。
- 恢复时不把视频文件访问权永久保存；需要视频时要求重新选择或重新走现有安全授权流程。
- 「查看差异」可只读显示处理前/后，未确认前不能改变字幕状态。
- 「稍后处理」保留草稿，不清除文件，当前会话内不反复弹窗。
- 「丢弃草稿」必须二次确认实际删除的对象与不可恢复后果；只删除当前应用管理的那个草稿，绝不删除原字幕、用户视频或其他工作区草稿。
- 如果只有草稿而来源路径已不存在，提供“以独立恢复内容打开并另存为新 SRT”的明确方式，但不伪造已验证来源状态。

## 4.3 外部修改检测

在导入原文件时记录**字节级 SHA-256**（或经过论证的同等级指纹），辅以大小与修改时间。重新打开/恢复前，重新读取与核对原文件。不要仅凭文件名相同或 mtime 相同就默认为安全。

| 情况 | 默认行为 |
|---|---|
| 原文件哈希未变化 | 允许正常恢复草稿 |
| 原文件内容发生变化 | 显示冲突，不自动覆盖；提供差异对比、恢复到独立草稿、另存为 |
| 原文件被移动/删除 | 允许以独立草稿方式打开，但提示无法验证原路径 |
| 草稿自身摘要不匹配 | 不加载为有效状态；隔离损坏文件，尝试最近完整快照 |
| 草稿 schema 版本未来/不认识 | 不强行解析；提示版本不兼容且不删除 |
| 同名不同路径 | 不视为同一文件；按原文件指纹/路径归属处理 |
| 有新编辑但上一轮 flush 尚未结束 | 只有最新匹配 revision 的提交结果才可以清除 dirty/恢复记录 |

原文件发生变化时，不要自动合并新旧字幕（容易产生无声数据破坏）。本轮只做明确的保守冲突处理。不同 Windows 路径大小写、盘符、UNC、符号链接应按现有路径安全约束处理。

## 4.4 生命周期边界

- 正常另存为成功后，只有当导出确实包含**当前最新 revision**，才允许把对应草稿标记为已解决并进行受控清理；导出失败或导出到不同文件的竞态中不能丢失最新草稿。
- 用户选择「取消关闭」时，保留当前草稿与内存状态。
- 用户选择「放弃未保存修改」时，明确确认后可删除相应草稿；不能把“关闭窗口”天然视为同意删除。
- 用户从时间轴切换其他文件时，先 flush 或显示保护失败，再允许继续；不得因卸载 React 组件而丢失待写操作。
- 已删除字幕条目、撤销后的状态、重做后的状态都必须能正确恢复到最近**已提交的编辑版本**。
- 意外断电发生在 debounce 窗口内的最后一小段未提交写入可能无法保护；文档必须如实说明，不能宣传“零数据丢失保证”。
- 草稿恢复服务的关闭时机不与 `srtmedia` 授权撤销混为一谈；关闭视频权限不应清除字幕草稿。

## 4.5 UI 状态建议

- `未修改`：没有待保存字幕变更。
- `草稿保护中…`：有提交的编辑但还没完成本地保护。
- `草稿已保护 · 14:32`：对应 revision 写入并通过完整性验证。
- `草稿保护失败 · 重试`：失败后存在风险，必须显眼但不过度弹窗。
- `已恢复草稿 · 尚未导出`：明确区分自动保护和正式导出。
- `原字幕已在外部修改`：阻止不经确认的覆盖式保存。

**自动保护不等同于正式导出**。UI 必须始终让用户知道“当前编辑保存为草稿”和“已经导出 SRT 文件”的差异。

# 5. Gate 3 — v0.6.1：Windows 与媒体稳定性专项

本阶段以发现和修复**可复现缺陷**为目标，不追求盲目增加播放器功能。

## 5.1 保留现有媒体安全边界

- 继续使用当前 `srtmedia` 受限媒体会话、Range / Seek、读取范围校验和撤销授权逻辑。
- 不开放全盘媒体目录，不保存永久授权 token，不将完整视频装入浏览器内存。
- 新增草稿服务不得让本地视频路径泄露到非受信的日志、遥测或草稿文件。
- 视频加载失败不能妨碍字幕时间轴编辑和草稿恢复。
- 页面卸载、切换文件、重新打开、退出、取消选择与播放失败时都要释放旧会话和文件句柄；旧 token 必须失效。
- 如果修改 Rust 代码或权限配置，保持已有测试及其安全断言，不要为了修复易用性而削弱安全校验。

## 5.2 Windows 验收矩阵

**优先测试：**

1. Windows 11：正式安装版与便携 ZIP 解压版，真实文件选择、编辑、自动保护、异常结束、重开恢复、导出与源文件哈希校验。
2. 100%、125%、150%、200% DPI：时间轴布局、弹窗、恢复面板和快捷键可用性；特别关注最小窗口 900×620。
3. Windows 10：在可获得的真实环境中验证 Tauri/WebView2、视频播放和草稿服务；未获取真实主机时记 `BLOCKED`。
4. 干净 WebView2 运行时：验证安装器依赖检查及故障提示；若无法提供完全干净环境，记 `BLOCKED`。
5. Windows 休眠/恢复：恢复后播放时钟、媒体句柄、Range、草稿写入状态正确；定时器恢复后不会重复提交旧 revision。
6. 受限用户权限、中文路径、空格路径、UNC/网络路径、只读目录、磁盘空间不足、文件被占用、文件被外部修改。
7. 多视频反复选择/取消/重开、快速 seek、播放结束、A/B 循环，在同一安装会话中检查资源释放和错误状态。

**不要宣称某种容器/编码全系统支持**。现有 Windows 11 技术实验中可以播放的 MOV/MKV/HEVC 样本，不代表所有机器都可解码。出错时保持字幕编辑功能可用并给出清晰、可操作的信息。

## 5.3 原生测试与故障注入

- 使用受控测试配置和独立临时目录，不操作真实用户 AppData 或真实字幕文件。
- 增加模拟异常退出/kill 进程后的重开恢复测试；恢复流程应覆盖**安装版与 ZIP 便携版**。
- Rust 草稿服务加入中断点注入：临时文件未写完、写完但未提交、manifest 更新前后、旧版本清理时崩溃、文件被占用、无权限、磁盘满或模拟 I/O 失败。
- 验证任何故障之后仍能恢复到**最近已确认完整保存**的版本，且旧源 SRT、旧成功发布包均不被破坏。
- Rust 媒体协议回归测试必须保留对路径穿越、junction、UNC/设备路径、未授权、过期会话和 Range 越界的覆盖。
- 用自动化核验测试前后的**源 SRT/视频 SHA-256**，不能仅靠界面提示“成功”认定未改原文件。

## 5.4 性能测试与解释

- 复用现有 `npm run benchmark`，控制测试机器、版本、并发后台负载、样本、预热次数和记录方式。
- 对时间轴 500 / 5,000 / 10,000 条字幕，测量打开、连续编辑、debounce 草稿写入、恢复与重新渲染的延迟。
- 建议对 50,000 条字幕运行处理引擎基准，但不要求在 UI 一次渲染所有条目。
- 记录草稿体积、峰值内存、写入次数、平均与 P95 保存延迟、恢复延迟和磁盘使用情况。
- 不要捏造绝对性能提升；先建立可重复基线。有回归则分析并修复，有环境差异则注明实验条件。

## 5.5 v0.6.1 交付门槛

- 自动保护与恢复可用，外部修改/损坏草稿/异常关闭都有明确处理。
- 现有工具箱、时间轴、媒体播放、A/B 循环、导出与安装版回归不退化。
- 已跑完本机可执行的单测、浏览器回归和 Windows 原生验收。
- 正确同步版本与文档；生成专门的 `docs/TIMELINE_V0.6.1_QA.md`，记录测试环境、Git SHA、测试命令、真实/模拟场景、通过数、失败/阻塞项。
- 在所有必需 Gate PASS 后再生成/替换 `release-output/` 的 v0.6.1 最新产物，并安全提交、推送、合并主线；若环境缺失导致发布 Gate 阻塞，保留最后成功产物并报告 BLOCKED，不假称版本已正式验收。

# 6. Gate 4 — v0.7.0：播放位置设定字幕起止时间与高效导航

**前置条件：** 已经从 `main` 的 v0.6.1 稳定基线创建新开发分支；草稿恢复、事务编辑、字幕导出和原有媒体播放均可用。

## 6.1 用当前时间设置字幕开始/结束

在时间轴已有单字幕选中状态下提供两个明确按钮：

- **将当前时间设为开始**。
- **将当前时间设为结束**。

用户预期：播放视频、暂停在说话开始或结束位置，点击一次即可精确设置当前字幕对应时间；不需要手动输入时间码。

实现语义：

1. 已关联可播放视频时，从真实 `HTMLMediaElement.currentTime` 或现有受控媒体时间 API 读取当前播放时间，在用户实际点击时捕获，转换为整数毫秒；不要使用可能晚一帧的 React 旧状态作为唯一事实来源。
2. 没有关联视频时，可从时间轴游标设置，按钮文案明确提示来源是「时间轴当前位置」，不要错误显示「视频当前位置」。
3. 一次操作只修改被选中的**单条字幕**；多选时禁用或显式要求切换到单条，避免无意对所有字幕设置同一个端点。
4. 修改开始时间默认保持结束时间不变，修改结束时间默认保持开始时间不变；如果 `endMs <= startMs`、产生负时间或超出可表示范围，默认拒绝提交并显示原因。不得自动移动另一端、静默把负值裁剪为 0 或删除条目。
5. 已有重叠字幕可以保留，但需要显示风险；新增重叠要标记「本次造成」而不是把所有历史问题归咎于本次操作。
6. 新时间通过现有编辑 Command / Transaction 一次提交，**一次操作只产生一步撤销**；提交后触发 v0.6.1 草稿保护，未正式导出前保持 dirty。
7. 视频播放位置不必因“设置字幕开始/结束”而跳动；只有用户选择「跳转到字幕」时才发生 seek。
8. SRT 时间精度是毫秒；不宣称拥有实际视频的逐帧精确时间戳。高刷新率视频播放期间的微小 mediaTime 差异可在 UI 说明。

## 6.2 字幕导航与快捷操作

复用已有选中、滚动定位、字幕列表虚拟化和视频 seek 逻辑：

- 上一条 / 下一条字幕：可在工具栏点击，支持键盘快捷键。
- 从视频播放位置定位当前/最近字幕：对于字幕间隙，明确选择最近条目策略，不随机跳转。
- 「选中字幕后跳转至起点」作为显式按钮或设置选项，避免用户仅点击列表就导致视频不断跳动。
- 键盘微调继续复用 v0.6.0 的已有实现，不要复制新一套快捷键和撤销队列。
- 明确快捷键文档；建议用不与浏览器/系统冲突的组合键，并允许后期扩展。**不要将单个字符键在输入框内强制截获**。例如快捷键处理应检测 `input`、`textarea`、`contenteditable`、模态对话框、IME 输入法组合状态及焦点上下文。
- 快捷键必须提供等价的可点击按钮和 tooltip，并且拥有可访问名称。

建议的默认映射（仅候选，需先审计已有快捷键冲突）：

| 操作 | 候选快捷键 | 备注 |
|---|---|---|
| 上一条字幕 | `Alt + ArrowUp` | 焦点在文本编辑区时不抢占 |
| 下一条字幕 | `Alt + ArrowDown` | 同上 |
| 设开始 | `Alt + [` | 若与平台冲突则调整 |
| 设结束 | `Alt + ]` | 若与平台冲突则调整 |
| 预览当前字幕 | `Shift + Space` | 不影响普通空格播放/暂停 |
| 拆分当前字幕 | 先提供明确按钮；快捷键可后补 | 有确认/预览，不宜误触 |

## 6.3 错误和边界

- 未选择字幕：禁用“设起点/终点”，提示先选择。
- 没有视频但时间轴游标存在：可用游标时间，明确文案。
- 当前时间为 `NaN`、`Infinity`、媒体未加载状态或负值：禁用/拒绝，不写入非法数值。
- 视频临时缓冲或播放 seek 待完成：确保捕获状态可解释，避免使用过期时间。
- 快速连续点击：每次只提交已验证的最新结果，不丢撤销事务顺序。

# 7. Gate 5 — v0.7.0：选中字幕区间预览与字幕拆分

## 7.1 选中字幕区间预览

在现有视频预览控件附近增加「预览选中字幕」：

- 选中某条字幕后，用户可以播放 `[startMs - preRoll, endMs + postRoll]`，默认前后各 300–500ms（具体默认值根据当前 UI 易用性选择并记录）。
- 提供「播放一次」及可选「循环预览」；如果视频总长未知，降级不应造成无限 seek。
- 播放区间须裁剪到 `[0, videoDuration]` 的有效媒体范围，字幕本身时间**不能因预览而被修改**。
- 现有 A/B 循环必须保持完整：开始选中预览时暂存旧 A/B 状态并暂时挂起，退出选中预览后恢复，不能覆盖用户手动设置的 A/B 点。
- 用户停止、切换字幕、关闭视频、切换工作区、跳出区间或显式取消时，要正确停止预览并恢复之前播放控制状态；不允许留下后台循环或多重计时器。
- 播放基于现有视频时钟同步机制，不能在多个 `setInterval` 中独立驱动时间轴与字幕叠加。
- 无视频文件时，预览按钮禁用并说明“请先关联视频”；普通字幕时间轴编辑仍可正常进行。
- 当字幕超出视频边界、视频长度不足或解码失败时，给出可理解错误；不裁剪字幕文件本身。
- 使用原来的 `srtmedia` 会话，不能新增额外持久文件授权。

## 7.2 在当前时间拆分字幕

目标：用户把播放头定位在某句话中间，需要将一条字幕分成前后两条。

**数据安全原则：不能为了自动拆分时间就擅自复制或丢失字幕正文。**

建议交互：

1. 只允许选中**单条字幕**拆分。
2. 当 `startMs < splitMs < endMs` 时提供拆分，等于边界、过短或无效时显示原因。
3. 时间区间拆成 `[startMs, splitMs]` 与 `[splitMs, endMs]`，必要时依据现有 SRT 端点和播放规则处理相邻边界，不人为添加不必要的时间间隙。
4. 出现一个轻量拆分确认面板，左侧和右侧分别显示两条字幕的文本。可以根据当前文本光标位置建议拆分点，但必须允许用户手动调整。
5. 若没有可靠的文本拆分点，不要自动将全文复制到两条字幕。可以预填左侧原文、右侧留空让用户填写；**正式确认前两侧文本必须符合当前字幕有效性规则**。若允许空字幕，必须明确提示这是用户刻意选择，而不能无提示生成。
6. 可用显示时长过短等软性诊断提示，但最基本的硬约束是 `startMs < splitMs < endMs` 且时间均为非负整数毫秒。
7. 保留原始字幕的稳定 ID 给左侧或按现有命令规范处理；右侧获得新的稳定 ID，后续重编号按现有导出服务统一处理。
8. 拆分完成后选中后半段，更新列表/时间轴一次；整体必须是**一个可撤销事务**，Ctrl+Z 能把两条恢复成原始一条且恢复正文/时间。
9. v0.6.1 草稿保护只保存提交后的两条新字幕；不保存弹窗未确认的半成品。
10. 一旦取消或验证失败，不修改文档、dirty、撤销栈或持久草稿。

应覆盖中文多行、英文空格、emoji、组合字符、CRLF/LF 语义、拆分点在开头或末尾、全文只有一个字符，以及 Unicode grapheme 断点。不要在 UTF-16 代理项中间硬切分 emoji。

# 8. Gate 6 — v0.7.0：两点校准（P0 核心功能）

## 8.1 功能定义

用户遇到字幕与视频不只是恒定偏移，而是**开头对得上、结尾逐渐偏离**的情况时，可以指定两对同步点：

- 字幕时间 `s1` 对应视频时间 `v1`。
- 字幕时间 `s2` 对应视频时间 `v2`。

按线性映射一次性调整字幕开始/结束时间，解决恒定偏移和线性漂移。

**数学定义**：

\[
a = \frac{v_2-v_1}{s_2-s_1}, \quad b = v_1-a s_1, \quad t' = \operatorname{round}(a t+b)
\]

其中 `s1,s2,v1,v2,t,t'` 单位均为**整数毫秒**。建议用 `t' = round(v1 + (t-s1)*(v2-v1)/(s2-s1))` 的稳定形式计算，结合数值安全/溢出检查；不多轮累计浮点误差。

## 8.2 输入 UX

建议使用轻量向导或单一可折叠工具面板，不占用第四个常驻属性栏：

1. 选择第一个字幕锚点，例如“当前选中字幕开始时间”，点击“记录字幕时间”；将视频停在对应说话位置，点击“记录视频时间”。
2. 重复记录第二对锚点。
3. 显示两组 `(字幕时间 -> 视频时间)`，以及估算的偏移、缩放倍率和跨度。
4. 选择作用范围：**全部字幕（默认）** 或 **当前选中的一组字幕**；如果选择区间范围，要清楚说明边界处理与跨界字幕是否包含。
5. 点击“计算预览”后显示修改条数、首尾时间示例、持续时长变化、引入的新重叠/非法条目数。
6. 用户确认后作为**一个编辑事务**应用；再次点击不能在未经重新选择基线的情况下把同一映射重复叠加。

### 交互保护

- 用户可以手动输入 4 个毫秒时间点，也可以从当前选中字幕与播放位置记录。
- 两个字幕锚点不能相同，即 `s1 !== s2`，且建议要求锚点间隔达到合理阈值（例如 1 秒）以避免极端放大噪声；跨度不足时拒绝或强提醒。
- 必须满足 `a > 0`，禁止时间倒序变换。倍率明显偏离 1（例如低于 0.8 或高于 1.2）要显示强警告；不以任意数字自动裁断用户数据。
- 所有结果检查 `Number.isSafeInteger`、非负时间、`startMs < endMs`，以及输出格式的可表示范围。
- 若变换产生负时间或无效区间：**默认禁止执行**；允许用户重选锚点或选择已有工具中明确提供的替代修复策略，不允许静默截到 0、交换开始结束、删除条目。
- 计算覆盖每条字幕的 `startMs` 和 `endMs`，不能仅校准开始时间而保持旧结束时间，除非用户明确选择不同算法（本轮不要引入）。
- 显示原先就存在的重叠与本次新产生的重叠，不能把所有旧问题当作新结果或静默压平。
- 默认只变更时间，不修改文本、cue ID、原格式、编码、换行符；导出仍交给现有文件服务处理。

## 8.3 预览与提交

- 提供处理前/后两列或复用现有逻辑差异预览；高亮新的时间而不是重写一个 diff 组件。
- 对 10,000 条以上字幕使用合理的分页/虚拟列表或抽样统计；不得一次渲染全部 DOM。
- 使用**当前编辑会话某个明确基线 revision** 计算结果。用户在预览期间若继续编辑其他字幕，则预览自动失效并要求重新计算，不能在过时 snapshot 上覆盖新变化。
- 确认后通过现有 Command 机制一次性提交，撤销一次恢复全部条目原时间，重做一次恢复映射后的时间。
- 按 v0.6.1 机制保护本次提交草稿，同时保持手动导出和源文件保护策略不变。
- 保留原有视频加载状态，应用校准时不要自动更换媒体文件、修改视频时长或破坏 A/B 循环设置。
- 对大量字幕优化 O(n) 计算并避免每条分别进入 React store/撤销历史，应该一次生成/提交完整事务结果。

## 8.4 关键测试样例

1. 纯偏移：`s1=1000, v1=2000, s2=11000, v2=12000`，结果所有时间增加 1000ms。
2. 漂移：`s1=0, v1=0, s2=10000, v2=10500`，乘数 1.05，包含每条字幕开始与结束的时间变化。
3. 两对锚点时间相同或倒序导致倍率非正：拒绝。
4. 整体校准后首条时间小于 0：拒绝，不修改任何字幕。
5. 锚点跨度极小、倍率异常、时间超出整数安全范围：明确提示。
6. 包含已有重叠但校准没有新增非法项：保留并警告，不自动删除。
7. 校准产生新的重叠或短时长：按诊断规则展示并区分处理策略。
8. 用户在预览之后又修改字幕：旧预览必须失效。
9. 一次校准、一次撤销、一次重做：字幕时间、正文、ID 和 dirty 状态一致。
10. 10,000 / 50,000 条字幕的内存、运行耗时与 Worker 选择合理，不产生每条一条撤销记录。

# 9. Gate 7 — v0.7.0 UI、可访问性与完整业务闭环

本轮是在已有**极简工具箱 + 独立时间轴工作区**上增强，不是重新做一个复杂的专业字幕编辑器。

## 9.1 UI 原则

- 主导航保持不变，时间轴入口保留其现有位置。
- 新增工具尽量放到时间轴已有的**选中字幕操作栏**或一个可折叠的「校时工具」区域。
- 用户正常播放/拖动字幕时，不展示复杂双点公式；仅进入「两点校准」时呈现锚点字段、倍率和差异预览。
- 「设置为开始」「设置为结束」「预览选中字幕」「拆分字幕」「两点校准」必须有明确图标、文字标签、禁用原因和键盘焦点。
- 不遮挡视频、时间轴或字幕列表的主要工作空间。窗口最小 900×620 时仍能访问核心功能；缩放 DPI 125/150/200% 时不丢失确认按钮。
- 所有操作的结果都进入统一的 dirty/undo/redo/草稿保护状态机；不能分别维护多个“是否修改”的局部 bool 导致状态不同步。
- UI 文案区别「草稿已保护」「正式字幕已导出」「本次操作未生效」「存在时间冲突」。
- 如果视频不可用：仍可进行已有时间轴编辑、字幕导航和基于游标的时间设定；依赖实际播放的区间预览应显示不可用原因。

## 9.2 可访问性和交互质量

- `button`、时间输入、对话框有对应名称与可见焦点。
- 拆分和两点校准可以全键盘完成；不能依赖仅鼠标拖动。
- 不抢占文本编辑区、中文输入法组合输入或系统快捷键。
- 所有异常都应保留用户输入/已填写的锚点数据，方便修正后重试。
- 取消模态框、按 Escape、切换工具时不应悄悄提交或丢失未确认的编辑。
- 对无效输入显示具体边界，而非仅 toast“发生错误”。
- 两点校准/拆分等批量或结构变更完成后，保留清晰的撤销入口。

5. `release-output/` 不放用户的草稿、缓存、媒体、测试视频、debug logs、历史版本、Git 源码备份。
6. 发布目录内的无关/未知文件不得无条件删除；沿用现有受信白名单/清理策略，必要时报告人工确认。
7. 执行 `npm run disk:report` 并记录发布前后占用。`clean:outputs`、`clean:release-cache` 等命令先检查实际行为，优先运行 dry-run 或精确清理。
8. Rust `src-tauri/target/` 可能占用大量空间，但不能随便删除整个 `target/`、全局 Cargo 缓存、未知目录或用户工作区。允许新增**仅针对本仓库明确生成的过期中间文件**的受控清理建议，必须有可预览清单与安全边界。
9. 草稿自身另受第 3 节的有界存储策略控制；清理旧构建**永远不等于清理用户未恢复字幕草稿**。
10. 不需要为了本轮两个小版本保留两份历史发布文件；Git 历史和 QA 文档负责留存版本证据，`release-output/` 只放最后一次成功的交付件。
