# 1. 产品目标和严格边界

## 1.1 产品形态

现有 SRTTools 是**极简 Windows 字幕文件工具箱**。新增一个相对独立的**字幕校时工作区**，形成两种清晰的使用方式：

- **工具箱模式（默认）**：保留首页、全部工具、批量处理、预设、组合流程、处理记录、设置及现有操作路径。
- **时间轴工作区（新增）**：对单个字幕文件进行可视化校时、正文和时间编辑、撤销重做、安全导出；v0.6.0 可额外关联本地视频同步校对。

导航新增清晰入口「字幕时间轴」，但不把全部原有工具迁移到时间轴里。用户从任何入口仍可使用原来的工具箱。

## 1.2 明确不开发

- 视频剪辑、视频转码、视频烧录/压制字幕、媒体文件修改、云端视频服务。
- 专业 NLE 多轨道编辑器、音频波形、复杂视频特效、逐帧精确校时承诺。
- 自动语音识别、AI 翻译、AI 音频对齐或远程模型调用。
- 复杂媒体解码/播放器内核（FFmpeg/MPV/VLC）第一版不引入，除非经过明确技术验证和后续独立决策。
- 让视频播放成为使用普通工具箱的前置条件。

## 1.3 两阶段定义

| 版本 | 必须交付 | 明确不属于该版本 |
|---|---|---|
| **v0.5.0** | 可视化字幕块、缩放滚动、选中、拖动及边缘调整、正文与精确时间编辑、插入删除、撤销重做、诊断、安全导出 | 真实视频播放与媒体协议 |
| **v0.6.0** | 用户选择本地视频、原生安全访问、播放暂停、跳转、字幕叠加、播放指示线同步、倍速/音量、A/B 循环、真实 Windows 视频验收 | 波形、视频转码、多轨视频编辑 |

两阶段都必须保持工具箱现有功能完整、旧数据可读取、设置/预设/工作流不损坏。

type TimelineMode = 'move' | 'trim-start' | 'trim-end';

interface TimelineViewport {

interface TimelineSession {

- 不将 `<video>` 元素、二进制视频数据、播放器帧或循环播放回调放入 Zustand。

# 4. v0.5.0 — 可视化字幕时间轴 MVP

## Gate 1：纯 TypeScript 时间轴核心

### 4.1 坐标、缩放、滚动

实现独立函数（具体命名可调整）：

```ts
function msToX(timeMs: number, viewport: TimelineViewport): number;
function xToMs(x: number, viewport: TimelineViewport): number;
function validateCueTimes(startMs: number, endMs: number): { valid: boolean; reason?: string };
function getVisibleCues(cues: readonly SubtitleCue[], startMs: number, endMs: number): SubtitleCue[];
```

要求：
- 横轴是真实时间比例，而非条目序号。
- 使用有限、非负、整数毫秒；运算中允许有限浮点像素，但落盘时四舍五入成整数毫秒。
- 缩放按钮与 Ctrl+滚轮/合适的快捷键共用同一套逻辑。缩放时尽可能保持鼠标指向的时间不漂移。
- 支持时间轴横向滚动与“适应全部字幕”功能；时间长度根据字幕末尾和已关联媒体时长取合理上界，但不能因超出媒体而隐藏字幕。
- 保护极短字幕块的可点击宽度，与实际时间宽度分离（视觉最小宽度不得改变保存时间）。
- 时间刻度应随缩放自动选用合理间隔，避免文字重叠。
- 渲染前只计算/挂载可见时间区间的字幕块，可预留少量 overscan，不能一次将数万条字幕都挂载。
- 对同时段重叠的字幕按纯视图布局分配显示层级，不隐式改变任何时间。
- 加入控件和屏幕阅读器可识别的可访问名称。

### 4.2 拖动语义与边界

| 操作 | 语义 | 数据变化 |
|---|---|---|
| 拖动字幕块中部 | 平移 | `startMs`、`endMs` 同步加相同偏移，时长不变 |
| 拖左边缘 | 调整入点 | 仅修改 `startMs`，须保持 `< endMs` |
| 拖右边缘 | 调整出点 | 仅修改 `endMs`，须保持 `> startMs` |
| 点击字幕块 | 选中 | 与字幕列表双向联动 |
| Shift/Ctrl 多选 | 多字幕选中 | 多条移动同一偏移，保留各自时长与相对间隔 |
| 空白处点击 | 定位 | 更新播放指示线/当前预览时间 |

具体要求：
- 使用 Pointer Events、`setPointerCapture` 和统一的拖动事务；处理 `pointerup`、`pointercancel`、Esc、窗口失焦。
- 拖动中只改变临时预览状态，**鼠标松开只提交一个编辑事务**，避免每帧入撤销栈。
- 负时间、结束时间小于等于开始时间、无穷数、NaN、时间溢出等为无效状态，必须拒绝提交或显示明确的策略选择；不得偷偷把所有值归零。
- 允许重叠但标记警告；不能自动推动相邻字幕“避让”。
- 多选移动若任何一条会越界，默认**整体拒绝提交**，而不是某些条目移动、某些不动。
- 时间吸附可作为 P1 开关；如实现，默认关闭，至少支持刻度和邻近字幕边界，并显示吸附反馈。
- 拖动中不要不断重排整个字幕列表和重算全量检测；提交后调用已有校验器获取诊断。

### 4.3 Undo/Redo — 编辑事务

建立可测的命令或快照差分管理：

```ts
interface CueEditCommand {
  type: 'move' | 'trim' | 'text' | 'insert' | 'delete' | 'batch-move';
  before: ReadonlyArray<SubtitleCue>;
  after: ReadonlyArray<SubtitleCue>;
  affectedIds: string[];
}
```

- 以上只是概念，内部应避免每次复制整个文档；可保留受影响条目和顺序变化信息。
- Ctrl+Z 撤销一次拖动；Ctrl+Y / Ctrl+Shift+Z 重做；修改后新提交应清空 redo。
- 删除、插入和文本修改都必须可撤销。
- 撤销上限应受控（例如默认 100 个操作或按内存预算限制），不因长期会话无界增长。
- `isDirty` / 未保存状态要基于草稿与最后成功保存版本的关系；撤销到完全一致可恢复为未修改状态。
- 失败的编辑事务不能污染 undo/redo 栈。

**Gate 1 验收：** 不依赖浏览器 UI，可通过 Vitest 验证坐标、可见范围、所有编辑事务、边界与撤销重做。

- 上方字幕列表和检查面板可调宽；下方时间轴可调高度，最小尺寸有合理降级布局。
- 不新增永久常驻的复杂第四面板。
- 字幕列表、时间轴、检查器共用选中 ID 和光标时间状态。
- 列表支持快速搜索、滚动定位、当前选中高亮。
- 当前字幕的文本字段支持多行编辑，失焦、确认、取消语义明确。
- 时间字段支持用户友好的 `HH:MM:SS.mmm` / 现有时间格式输入与校验；不能因非法输入直接丢失原值。
- 列表支持插入字幕、删除字幕，且均受撤销管理；插入时默认时间不能覆盖已有字幕造成静默损失。
- 对重叠、超时和非法时间提供可见但克制的诊断；错误码/明细可展开，不能以红色背景代替说明。
- 空文件/未选择文件/读取失败/受限格式/无效结构显示明确引导，不出现空白死区。

### 4.5 快捷键

至少支持：
- Ctrl+O：打开字幕（上下文明确）。
- Ctrl+Z：撤销；Ctrl+Y / Ctrl+Shift+Z：重做。
- Delete：删除已选字幕（在文本输入框有焦点时不拦截）。
- Esc：取消拖动/退出临时编辑。
- 方向键：按可配置的微调步长移动选中字幕；建议预设 10ms、50ms、100ms，用户可在工作区选择。
- 快捷键不得抢占输入框、原有全局快捷键或系统行为。

### 4.6 状态与操作安全

- 切换文件、关闭窗口、切换工作区时，如果有未保存修改，应阻止误操作并提供「保存并继续 / 放弃修改 / 取消」；Windows 关闭路径要通过真实 Tauri 窗口事件验证。
- v0.5.0 不强制自动保存到原文件；默认另存为新文件，文件名安全且重名避让。
- 显示状态：文件名、字幕条数、解析警告、是否已修改、当前选中时间。
- 不把工作区编辑会话暴露为普通批量队列项；避免工具箱处理结果与未保存时间轴草稿互相覆盖。

**Gate 2 验收：** 浏览器和真实 Tauri 的“打开 SRT → 选中 → 拖动 → 编辑 → 撤销 → 导出”闭环可用。

# 5. v0.6.0 — 本地视频同步预览

> **硬性依赖**：v0.5.0 的编辑事务、字幕导出、Windows 原生验收必须先有可信基线；视频无法播放时，**时间轴依然必须完全可用**。

## Gate 4：先做本地视频访问技术验证（独立安全门槛）

不要先设计完大视频 UI 再发现 WebView2 的本地文件协议不支持跳转。先写一个仅用于验证的最小媒体组件或受控测试页面，形成 `docs/MEDIA_ACCESS_SPIKE.md` 并获得实际证据。

### 5.1 验证问题

1. 用户能否使用现有 Tauri 原生 dialog 或新受限命令**明确选择一份本地视频文件**？取消选择时会怎样？
2. 是否能在 Windows 正式安装版和解压运行版中读取该文件元数据、进行播放、暂停和任意 seek？
3. 本地资源服务是否支持视频所需的 **HTTP Range / 随机访问语义**（若所选方案依赖此能力）？记录 Range 请求、响应状态、`Content-Range`、长度和边界行为。
4. 加载大型文件时是否避免通过 Tauri IPC 将整个视频转成 `Uint8Array` / `number[]`、Base64、`data:` URL 或完整内存 Blob？
5. 目前 `tauri.conf.json` 的 `CSP` 未覆盖媒体源，使用新资源协议后，`media-src` / `connect-src` / `assetProtocol.scope` 是否安全且实际可用？
6. 用户关闭视频、切换文件或关闭窗口后，资源 URL、读取会话、媒体句柄能否释放；旧路径能否被拒绝？
7. Unicode 路径、空格、`#`、`?`、长路径、符号链接/重解析点、大小写不一致、网络盘等是否获得明确兼容结论？
8. `.mp4` 扩展名不等于可解码：H.264/AAC 的实际支持如何？HEVC/MKV/MOV/WebM 各自的结果是什么？
9. 浏览器预览开发模式与 Windows Tauri 正式运行模式有什么差别？不能把 Node 模拟或 Chromium Playwright 成功当成原生验证。

### 5.2 媒体访问的安全方案

首选：复用 Tauri 2 的**受限资产协议**（`convertFileSrc` + 适当 scope/CSP），但必须经最新官方文档和现有 Tauri 版本验证配置与运行时权限行为。

- 只允许用户本次明确选择的**具体文件路径**，不因简化实现而开放 `$HOME/**`、`$VIDEO/**`、整个磁盘或任意通配符访问。
- 对静态 `app.security.assetProtocol.scope` 无法表达单文件动态许可的情况，**不能用全盘 scope 填洞**；评估官方动态/持久化 scope 机制及其撤销语义。若确实不满足需求，再采用**经过审查的受限本地媒体读取/流服务**（例如单文件访问令牌、受限 URI Scheme、支持 Range 的 Rust handler），并写出安全与性能测试。
- 对路径做 canonicalize、普通文件验证、只读权限、适当大小及类型检查、绑定当前窗口/会话授权、处理符号链接或重解析点，以及请求路径遍历、跨会话访问。
- 采用会话级或不可猜测的资源标识，不暴露任意磁盘读取 IPC；即使知道其他路径也不能加载未授权文件。
- 如果允许某类本地视频的绝对路径通过前端 URL 映射，必须验证路径作用域严格受限，且文件关闭或切换后可撤销访问。无法立即撤销的官方机制必须在安全报告说明其实际边界，并采用安全替代方案。
- 必要的 CSP 只放行经过验证的媒体 scheme/origin，不使用 `default-src *`、`connect-src *`、放开脚本执行等宽松配置；若使用自定义媒体 URI，配置仅需要的 `media-src`。
- 遇到媒体访问失败，**仅降级为无视频字幕时间轴**；绝不自动联网、上传或全文件拷入内存。
- 所有新依赖都要评估许可、发布体积、性能和 Tauri 2 兼容性。

**严格禁止的便捷方案**：

```text
❌ 将 2GB MP4 调用原有字幕 select_files/read_dropped_files 读成 byte[] 再传 IPC
❌ 将完整视频编码成 Base64 / Data URI / Blob 以求能播放
❌ 将整个用户主目录/磁盘加入 Tauri assetProtocol.scope
❌ 添加不受限的 Rust read_any_path(path: String) 命令
❌ 使用隐藏 HTTP 服务监听所有网络接口且不校验访问令牌
❌ 自动复制视频到 release-output、仓库、AppData 长期缓存
```

### 5.3 Gate 4 必须通过的证据

- 正式 Tauri Windows x64 下真实本地视频：`loadedmetadata`、`playing`、`pause`、`seeking`、`seeked`、`ended`、`error` 事件有可靠记录。
- **不同文件大小、多个 seek 位置**都可以正常播放/跳转（特别是拖到接近结尾）。
- 证明没有一次性读取完整媒体文件；记录峰值内存或实际 IPC 消息尺寸的测试结果。
- 尝试通过修改 URI/令牌访问其他未选择的本地文件必须被拒绝。
- 关闭媒体后资源访问与句柄已受控释放；重复选择/关闭没有明显累积泄漏。
- 形成 `docs/MEDIA_ACCESS_SPIKE.md`：技术方案、关键配置、版本、样本、测试步骤、结果、未解决兼容性和安全决定。

**若原生媒体 Gate 4 未通过：停止 v0.6.0 “完成并发布”动作，保留 v0.5.0 最后成功交付，不得用假播放器替代。** 可以提交安全的探索分支和报告，但不能把产品版本标为完整 v0.6.0。

## Gate 5：媒体服务与播放器

### 5.4 媒体状态机

建议把媒体从时间轴编辑会话中分离，仅管理最小状态：

```ts
type MediaStatus =
  | 'idle' | 'loading' | 'ready' | 'playing'
  | 'paused' | 'seeking' | 'ended' | 'error';

interface MediaSession {
  status: MediaStatus;
  durationMs?: number;
  currentTimeMs: number;
  volume: number;          // 0..1
  muted: boolean;
  playbackRate: number;
  error?: string;
  loop?: { startMs: number; endMs: number };
}
```

不要把完整媒体绝对路径作为历史记录或遥测数据持久化；临时媒体选择状态可保留在内存中。媒体源句柄应与会话生命周期绑定，不复制到全局字幕文件队列。

### 5.5 HTML5 Video 首选实现

- 使用 `<video>`，`preload="metadata"`，不自动播放，用户主动点击播放后调用 `play()`，正确处理 Promise 拒绝。
- 读取 `duration`、`videoWidth/videoHeight`、`currentTime`、`paused`、`seeking` 等真实属性；处理 NaN、Infinity、空时长、损坏文件。
- 控件：播放/暂停、进度与指定时间跳转、音量、静音、倍速（至少 0.5×、0.75×、1×、1.25×、1.5×）、总时长、加载中、错误显示。
- 播放速度变更不改变字幕数据时间，只影响媒体播放速度。
- 关闭/切换视频时按序暂停、解绑监听、取消 frame callback、移除 `src`、调用 `load()` 清空媒体状态、释放/撤销资源许可或令牌。
- 用户取消选择或视频不支持时保留字幕草稿和既有时间轴交互；提供重试与更换视频入口。
- 无音轨/黑屏/损坏文件需分清可恢复情况，不能误判为字幕文件损坏。
- 视频适应容器 `object-fit: contain`，字幕叠加必须始终置于有效画面区域，避免被控制栏挡住；窗口 resize 和高 DPI 缩放均可用。

### 5.6 文件格式支持声明

- **主要验收格式：MP4（H.264/AAC）**，以实际系统 WebView2 能力为准。
- WebM 可以测试并作为经过验证的扩展格式支持。
- MOV、MKV、HEVC 等均不得只凭扩展名宣称“完全支持”。发现不支持时清晰提示“此视频编码/容器可能不受当前 Windows/WebView2 支持，请转换为受支持格式后重试”。
- **不内置 FFmpeg/转码器**。用户自己选择或提供可用媒体文件，SRTTools 不替用户改写视频。
- 明确当前功能“本地视频校时预览”，不是万能播放器。

## Gate 6：视频 / 字幕 / 时间轴同步

### 5.7 单一时间来源

**当媒体存在且正在播放时，视频元素的实际媒体时间是唯一真实播放时间源。**

```text
HTMLVideoElement currentTime / frame metadata
            │
            ├── 更新播放指示线（Playhead）
            ├── 查询当前活跃字幕 Cue
            ├── 更新视频叠加字幕
            └── 可选地使字幕列表跟随播放（节流）

用户点击/拖动时间轴空白 → requestSeek(timeMs)
            │
            └── 设置 video.currentTime（合法范围内），等待 seeked 对齐 UI
```

- 可用时采用 `requestVideoFrameCallback` 获取媒体帧时间；不支持时降级至 `timeupdate` 或经过节流的其他手段。
- 不是严格逐帧保证；不要宣传“帧级完全精准”。暂停、seek 后应立即使用 `currentTime` 更新画面，不必等待下一次 frame callback。
- 避免每帧调用 Zustand 导致整个应用重渲染；播放指示线/覆盖字幕采用局部订阅、Ref、节流或其他低成本更新方式。
- seek 请求需要序列化/去抖，防止频繁拖动滑块触发积压的异步 seek；以最后一次用户意图为准。
- 媒体范围之外的字幕可以继续出现在时间轴中，并显示“超出视频时长”；不得自动删除、截断或调整字幕。
- 播放时间绝不能反向直接修改任何 `Cue.startMs/endMs`；只有用户显式执行编辑操作才改变字幕。

### 5.8 活跃字幕的判定与渲染

- 用 `startMs <= currentTimeMs < endMs` 作为单条 Cue 的活跃区间（末端开区间），保持同一约定用于时间轴与视频叠加。
- 支持字幕间隙：无活跃 Cue 时视频叠加为空。
- 支持重叠字幕：按明确规则展示多条字幕，避免乱序或覆盖；不修改时间。
- 支持多行、中文、英文、emoji；默认将字幕正文**作为文本渲染而非任意 HTML 注入**，防止文件里的 `<script>`/样式注入。
- 对可能存在格式标记的字幕正文采用安全解析/显示策略，不支持的控制标签不应执行。
- 保持可读字幕：适当半透明底、文字阴影、字体大小、行高；与原工具箱浅/深色主题不冲突。
- 查询活跃 Cue 可以使用按开始时间排序的索引/二分查询，不能每播放一帧无条件遍历所有万条字幕。

### 5.9 时间轴/视频互动

| 用户动作 | 预期效果 |
|---|---|
| 点击字幕列表条目 | 选中 Cue；按钮或快捷操作可跳到字幕开始时间 |
| 点击时间轴字幕块 | 选中，必要时暂停播放；不得无意改写 Cue |
| 点击时间刻度或空白 | 跳转当前播放时间，视频同步 seek |
| 拖动播放指示线 | 视频 seek，指示线和叠加按最新时间更新 |
| 拖动 Cue 中部或边缘 | 编辑草稿时间；视频可选择暂停，修改完成后同步选中状态 |
| 点击播放 | 从当前时间继续，音视频独立播放，不写入字幕 |
| 视频播放结束 | 指示线到末尾，状态 ended；不删除超出时长字幕 |

### 5.10 A/B 区间循环

- 用户可通过当前播放位置设置 A 点和 B 点，也可输入精确时间。
- 仅当 `0 <= A < B <= duration` 且时长合法时启用。
- 当播放到 B 附近，跳回 A 并继续播放；必要时考虑时间更新事件频率、精度和误差，不能死循环 seek。
- A/B 循环与普通视频 `loop` 属性分开，不能影响字幕数据。
- UI 显示 A/B 标记和“清除循环”入口；关闭视频后应清理当前循环状态。

# 6. 自动化测试、性能和 Windows 原生验收

## 6.1 测试原则

- 新增测试不能以 mock 成功取代原生能力证明。
- 核心时间计算、编辑命令、活跃字幕判定是**纯函数测试**；UI 交互通过 React 测试或 Playwright；文件授权、视频协议和播放通过 Windows Tauri 正式构建验证。
- 保持原有测试全部可执行，不能删除、跳过或放宽断言来让 CI 变绿。
- 测试视频使用自制、授权或生成的短样本，不将版权受限视频提交仓库；在需要时记录编码参数、生成方式及 SHA-256。大视频测试优先使用本地临时测试素材，不提交或纳入发行包。
- 每次完整质量验证都应记录 Git SHA、操作系统、架构、Node/Rust、WebView2 版本和执行命令。

## 6.4 Playwright / UI 测试

建立可复现的流程：

**v0.5：** 打开页面 → 导入固定 SRT → 点击 Cue → 拖动 → 修剪 → 验证时间输入 → Ctrl+Z → Ctrl+Y → 编辑正文 → 删除/插入 → 另存为（浏览器预览可验证下载语义）→ 解析输出并断言文本时间。

**v0.6：** 加载确定性测试视频 → 触发 `loadedmetadata` → 点击播放 → 校验字幕叠加 → seek 指定点 → A/B 循环 → 暂停 → 切换视频 → 检查未保存字幕仍保留。通过适当 mock 让 UI 行为稳定，但**不得把它写成原生媒体最终验收**。

## 6.5 Windows 原生测试

- Windows 中文路径、带空格和特殊字符的路径、长文件名、只读目录、文件正在被占用。
- 关闭窗口时未保存确认，取消关闭与继续保存的实际结果。
- 真实 MP4：播放、seek、字幕同步、视频切换、音量、A/B 循环、文件句柄释放。
- 视频损坏、无法解码、权限不足、文件被移动/删除的错误状态。

- 如果没有 Windows 10 / 干净 WebView2 环境，**明确列为未验证**而非自动宣称兼容。

## 6.6 性能目标与测量方法

不要盲目宣称“无限字幕”或“逐帧精准”。

- v0.5.0 至少对 500 / 5,000 / 10,000 字幕条目记录首次可操作时间、缩放/拖动交互响应、DOM 节点数量、JS 堆或进程内存（能够测量的环境）。
- 视口虚拟化：在保持固定视口时，挂载字幕块应主要随可见数量增加，而不是随总条目数线性增加。
- 对 10,000 条字幕，滚动/缩放不应导致持续几秒无响应；具体性能阈值应基于现有 `npm run benchmark` 基线和测试环境建立，而不是凭空编造数字。
- v0.6.0 测试播放期间的视频同步主线程开销，避免每帧重渲染整个页面。
- 在合适的 Windows 测试素材下验证大视频不会被一次性复制到 JS 堆/IPC；记录文件大小与内存增长。
- 发现真实性能瓶颈时先分析热点再优化，不引入大体积媒体依赖作为默认解决方式。
- 性能报告放在 `docs/` 或现有基准体系中；不要把大体积原始测试视频或长年累积的日志纳入 Git。

## 7.4 与现有发布脚本的额外契约（不能遗漏）

当前 `scripts/build-release.mjs` 的正式发布预检要求**已提交的干净工作树**，`--allow-dirty` 只能用于明确标记的开发验收，不是正式发布捷径；此外，发布脚本内已有固定的 `workflow` Windows UIA 冒烟和布尔字段要求。

- 先完成代码、测试、必要版本/配置变更并提交，再执行正式 `release:win`；不要在未提交源码上生成标称 clean 的候选构建。

- 如新增 QA 清单字段，需同步更新验证器、测试与向后兼容规则；历史已成功的 v0.4.0/v0.5.0 清单应仍可在构建失败时作为最后一次成功版本被验证，而不是被新字段错误判为无效。
- 如新增 Tauri `resources`、DLL、sidecar 或媒体许可清单，必须先增强经验证的资源白名单和 ZIP/便携版哈希库存，**不得关闭当前白名单检查**。本轮原则上不新增媒体运行时/FFmpeg sidecar。
- 每次代码或安全配置改动后都要重新构建验证；仅 QA 文字记录补充可遵守现有源码指纹排除规则，但不得修改历史证据以伪造构建通过。
- 合并 `main` 后检查源码指纹与发布状态是否一致；如果新的合并提交导致当前发布证据不再与主线匹配，应在干净的 `main` 上重新按原脚本验收，而不是绕过 SHA/指纹校验。

### 合并和远程校验步骤

1. 提交前再次检查 `git diff`、`git status`，只暂存本轮实际变更；生成产物和视频素材不得提交。
2. 推送功能分支至经验证的 `origin`，读取远端 SHA 确认成功。
3. 按当前仓库的 PR/保护策略合并回 `main`；如果允许本地合并，先 fetch 并处理远端更新，不能强制覆盖。
4. 合并后检查 `main` 的真实合并提交 SHA、版本检查和关键回归测试。
5. `git ls-remote origin refs/heads/main` 比对本地最终提交，报告一致或阻塞。
6. 更新工程记忆按 `wiki_memory` 协议保存完成事实和下一步，不泄露用户私有路径/敏感内容。
